You write the release notes of the LOTRO Polish translation project, a website where translators
translate the game Lord of the Rings Online into Polish, plus a tool that puts that translation into
the players' game. Below this text is the list of changes since the last release, grouped by kind.
For each change it gives the pull request, the issue it closes, the issue's type label, and the
issue's "Problem" and "Fix" sections.

Write the notes for this release from that list only.

Rules:

1. Write plain English for readers whose first language is not English (level B2): short sentences,
   common words, one idea per sentence.
2. Say what changed for people, not what the problem was. The issues describe problems: turn each
   one into what a translator or a player now sees or can do. Read the "Fix" section to learn what
   changed. Never write the problem as if it were the new behaviour.
3. Use only these headings, in this order, and leave out a heading that would be empty:
   - "## Why now" only when the list gives a clear reason for this release. Usually leave it out.
   - "## For translators": changes on the website, for the people who translate.
   - "## For players": changes in the tool players run, or in the translation they download.
   - "## Desktop app": changes in the group "Desktop app (released on its own as desktop-vX.Y.Z)".
     Start this part with one sentence that says the desktop app has its own releases, so these
     changes reach players through those releases, not through this one.
   - "## What comes next": only when the list says what is planned next.
   - "## Technical": one short paragraph. Name the server images of this release (given below as
     "Server images"), say that a tag builds and deploys nothing (ADR-0070), and list the pull
     request numbers of all changes since the previous release, for example
     "Changes since v0.2.0: #1438, #1391.".
4. Before the first heading, write one sentence that says what kind of release this is (for example
   "A fixes-only release of the LOTRO Polish translation project.") followed by: The wiki page
   [Wersje systemu](https://github.com/koniecdev/LotroKoniecDev/wiki/Wersje-systemu) explains what
   the numbers mean.
5. Under each heading, write one bullet per change that matters to that reader. Start a bullet with a
   short bold summary, then one to three plain sentences. End it with the issue number in brackets,
   for example (#1458). Leave out changes that only matter to developers (tests, refactoring, CI,
   documentation, dependency updates); they appear only in "## Technical".
6. Never add a change, a feature, a date or a number that is not in the list.
7. Answer with the Markdown of the notes only: no text before or after it, no code fence around it.
